# 实际运行结果

环境：本机 OrbStack Kubernetes，`iot-lab` 命名空间；模拟设备与实际 MQTT、FUXA、RTSP、PostgreSQL 服务。

## 已验证

- OpenAPI 在前后端开发前通过规范校验。
- 一次正常入炉：二维码经 RTSP 编码、传输、解码后识别；OPEN、CLOSE、RESET 均收到真实模拟设备反馈，形成成功记录。原始结果：`entry-success.json`。
- 一次 MES 质量拒绝：周期进入 BLOCKED，命令列表为空，未打开炉门。原始结果：`mes-rejected.json`。
- 停止 FUXA 进程后，三个设备均被业务端判定为 SCADA_OFFLINE，ready=false；测试后已恢复 FUXA。原始结果：`scada-offline.json`。
- 成功入炉后对门命令 topic 新建 retained-only 订阅，1 秒内没有收到旧命令；与发布版 retain 补丁及设备拒绝 retained 命令共同验证该路径。
- 人工清空模拟入口、关门和复位后，未完成周期以 ABORTED 结束，保留历史，没有伪造成功。
- 浏览器实际显示 RTSP/HLS 视频、设备状态、历史记录和 FUXA 动态点位。首次工作台检查未发现应用控制台错误。
- 有针对性的 Go 测试：设备命令重复、过期、旧 bootId、不同炉子目标、卡门；扫码两帧稳定识别；Telegram 429 重试与响应丢失后 unknown 状态。

## 未宣称的结果

- 未接真实 IP 摄像头或真实 PLC。
- 未提供真实 Telegram 凭据时，只验证本地模拟 HTTP 请求处理及持久队列，不能称为真实 Telegram 已收消息。
- 未运行连续 20 次验收、性能基准、消融、压力测试或完整故障矩阵。双炉目标隔离已做单元验证，未做双炉视频并发联调。
- 1 秒界面更新是配置目标，没有额外进行延迟基准测试。

SCADA 停机验证从 Pod 实际退出开始判定。仅发出 Kubernetes 缩容请求时，进程可能仍在终止宽限期内通过原有连接服务，不能把这段时间当作已停机。
